## 2026-11-18 — ядро v1.0.0

### Движок (ZapretLazyEngine)

- **Фазовый конвейер** (`Autopilot.ps1`): boot → update → preflight → testing → installing → monitoring; PID-lock; `status.json` каждый проход.
- **Прогресс в status.json**: stage/index/total/strategy — для строки статуса виджета.
- **Персистентность стратегии**: `state/strategy-history.json` (lastStrategy/lastGreen/testedAt); расписание retest `settings.testSchedule` (onboot / every3days / weekly / monthly) с матрицей ensure службы; выбор стратегии переживает перезагрузку.
- **Baseline-замер**: строка без обхода измеряется первой; fully-green baseline → обход не ставится, предыдущий удаляется, история очищается; baseline нельзя установить.
- **StrategyEngine**: аргументы winws — голые токены (потребители квотируют сами; раньше вложенные кавычки роняли службу с кодами 2/3/4); один retry на suite при таймаутах curl (провайдер теряет ~30% рукопожатий); `Measure-Baseline`; таймаут curl 4 → 6 с.
- **Обновления (UpdateManager)**: TLS 1.2+ на вызов, защита от zip-slip, проверка Authenticode + pin (fail-closed), ACL staging через SID; при замене payload сохраняются весь `lists\` и `utils\targets.txt` (списки замораживаются), donor-оверлей `state\seed-lists.json` после первой выдачи.
- **Безопасность**: `Protect-EngineTree` (icacls-закалка дерева, идемпотентно); строгая типизированная валидация команд трея с whitelist и причинами отказа; потолок 260 символов на имя стратегии; настройки `security.pinSha256`/`hardenAcls`; клэмпинг enum-значений; потолок 64 КБ на команду; fallback лога трея в `state\tray.log`; устойчивость к битому/пустому settings.json.
- **Preflight**: ACL на settings.json для интерактивного пользователя (владелец explorer.exe, fallback Users) — раньше SYSTEM-движок блокировал трей Access Denied.

### Виджет (ZapretLazyTray)

- **Первый трей + виджет**: командный канал tray→engine через `state\commands.json` (атомарно tmp+move).
- **Тёмный redesign v1**: карточка #1E1F23, рыжие акценты #E8720C, свои тёмные dropdown'ы (поле + попап), GDI+ текст, DPI-масштабирование.
- **Ретро dot-матрица**: 5×7 глифы из Consolas Bold, оранжевые точки, прокрутка переполнения; `settings.widget.fontStyle` dots|mono.
- **Шрифт** позднее унифицирован в Consolas 9 по спецификации дизайна.
- **Расписание тестов** в меню (подменю с галочкой, только Save-Config, без команд).
- **Автоскрытие после загрузки**: виджет всегда показывается на boot, скрывается после monitoring/error без записи `widget.visible`; ручной toggle отменяет.
- **Исправлен класс багов GetNewClosure**: обработчики `$script:` — только plain scriptblocks (StrictMode-крэш в динамическом модуле).

### Сборка и установка

- **Build-Exe.ps1**: слияние скриптов в самодостаточные (гейт коллизий имён, strip Export-ModuleMember, Get-Root → exe dir), компиляция PS2EXE в ZapretLazyEngine.exe / ZapretLazyTray.exe.
- **Register-LazyTasks.ps1**: регистрация задач планировщика (AtLogon), абсолютный System32 wscript с read-back проверкой, whitelist режимов; fallback `-UseScripts` для машин с Smart App Control (блокирует неподписанные exe — проверено контрольным hello.exe).
- **Setup.exe** (новый): один установщик с встроенным package.zip — `/InstallDir` `/DonorPath` `/Scripts` `/Start` `/Uninstall` `/KeepData`; авто-детект donor-папки; upgrade поверх сохраняет settings/state/zapret-core; дефолт `C:\zapret-lazy`.
- **Переименование проекта**: zapret-autopilot → zapret-lazy (exe, задачи, скрипты, пути, доки; старые имена задач авто-удаляются).
- **Доки приведены к факту кода** (имена задач, сигнатуры, ONSTART и т.д.).

## 2026-11-19 — v1.1.0 и дизайн v2

### Установщик: устойчивость и UX (утро)

- **Интерактивное меню**: запуск Setup.exe без аргументов даёт выбор Install / Upgrade / Uninstall / Quit (раньше неочевидно, что деинсталляция — только `/Uninstall`).
- **Автостарт после установки**: engine + tray стартуют сами в конце установки (`/NoStart` отключает); перед upgrade/stop корректно останавливаются оба процесса; удаление останавливает компоненты.
- **Защита от падений**: глобальный try/catch с логом `%TEMP%\zapret-lazy-setup\setup.log` и удержанием окна; `Invoke-NativeQuiet` против `RemoteException` от stderr системных команд.
- **Исправлены**: `$null -join` при UAC-перезапуске без аргументов; `Join-Path` на отсутствующий диск D:; **вложенные папки** `launcher\launcher` при повторной установке (слияние через `dir\*` — PS 5.1 `Copy-Item -Recurse` в существующую папку вложил копию; воспроизведено и исправлено).
- **Ярлык**: «Zapret Lazy.lnk» на рабочем столе при регистрации задач, удаляется при `-Unregister`.

### Иконки и брендинг

- **assets/zapret-lazy.ico** (16–256 px) вшит во все три exe (`-iconFile` в Build-Exe) — у процессов в диспетчере задач иконка лисы вместо дефолтной.
- **assets/tray-fox.png**: значок трея = лиса + бейдж состояния в углу; fallback-отрисовка без ассета.
- Лиса в шапке виджета вместо рыжего круга (14 px на старом макете).

### Движок: честность измерений

- **TCP timestamps**: `Enable-TcpTimestamps` (идемпотентно, вердикт по `$LASTEXITCODE`) — все стратегии используют `--dpi-desync-fooling=ts`, а stock `service.bat` включал timestamps через `netsh`, а lazy — нет. Вызов: начало `Invoke-StrategyTests` и `Install-ZapretService`.
- **`*-user.txt` списки**: `Initialize-UserLists` создаёт `ipset-exclude-user.txt` / `list-general-user.txt` / `list-exclude-user.txt`, на которые ссылаются аргументы стратегий (stock `service.bat :load_user_lists` делал то же).
- **Анализ логов тестовой машины** (stock zapret давал fully-green 36/36, lazy — 0): гипотезы timestamps/user-lists **опровергнуты** логом самой машины (оба применены с первого boot, разрыв 18/36 сохраняется, детерминировано: 6 целей зелёные, discord+youtube-web — никогда). Причина не найдена.
- **Инструментация**: `Engine TargetResult` (токены по целям/сютам), `UnexpectedWinwsCount` (второй winws делит WinDivert-потоки), `WinwsExitedEarly` с кодом выхода, `WinwsStopped count=0`. Живой re-test с новой инструментацией — pending.
- Дубликаты хелперов удалены из StrategyEngine (владелец — Preflight).

### Виджет: дизайн v1→v2

- **Перенос artboard'ов** (Kimi Design: artboard-running/checking/menu/indicators + SVG + spec.md): геометрия, Consolas 9 и иерархия цветом, состояния (зелёный круг / рыжая пауза / красный квадрат / рыжее колесо), нарисованные кнопки (точки/крест/chevron), тёмное меню-попап, full progress line с ellipsis в transitional-фазах.
- **Исправлено по живым тестам KimiCU**: меню не открывалось (StrictMode `$it.Separator`); клики по label не открывали dropdown; `Point` с тремя аргументами (арифметика в argument mode) ломал попап; JIT StrictMode в FormClosed (просроченная локальная `$popup`); null-owner меню трея отклонялся биндингом.
- **Индикатор checking** по требованию пользователя: не вращение, а три фиксированные дуги по 70°, ведущая `#FF9A3C` с глоу перескакивает на 120° каждые 500 мс. Меню переворачивается влево у правого края и вверх у нижнего.
- **Адаптивные значки трея**: run/pause/error/spin из тех же форм, `network.up=false` → error; атомарная замена, старые GDI-дескрипторы уничтожаются.

## 2026-11-20 — v1.3.8

- Обслуживание без перезагрузки: движок ждёт сеть перед проверкой обновлений (при позднем Wi-Fi обновление больше не пропускается и движок не завершается), проверяет обновления раз в сутки и после пробуждения, сверяет расписание проверок раз в час; «при запуске Windows» срабатывает и после сна дольше 30 мин.
- Пауза при VPN: если интернет идёт через VPN-туннель (Wintun, WireGuard, TAP, OpenVPN, xray/Happ и др.), zlazy останавливает обход и ждёт; после отключения VPN (5 с без VPN подряд) возвращает прежнюю стратегию или запускает проверку. VPN, включённый посреди теста, прерывает тест.
- Стратегия, выбранная вручную в виджете, запоминается до следующего тестирования и переживает перезагрузку.
- Виджет: знак паузы и строка `vpn: on · lazy paused`; индикатор статуса всегда на одном месте, текст выровнен влево сразу за ним.
- Быстрый старт: на загрузке сначала проверяется запомненная стратегия; если она полностью рабочая, обход включается сразу, без перебора всех стратегий.
- ACL проверяются через `Get-Acl` и переписываются только при расхождении (было ~8 с на каждом старте); трей стартует через 10 с после входа вместо 45 с.
- Установщик: анимированный индикатор перед текстом операции, окна результата и подтверждения в стиле установщика, без белого окна прогресса.
- Ссылка GitHub в меню ведёт на репозиторий проекта.
